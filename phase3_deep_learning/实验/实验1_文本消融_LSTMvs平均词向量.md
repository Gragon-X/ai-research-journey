# 实验 1：文本分类消融实验 —— LSTM vs 平均词向量

> 实验日期：2026-08-23　|　周次：第 14 周（深度学习收官）　|　方向：A 文本

## 一、实验目的

消融实验：把 LSTM 从情感分类模型中拆掉，换成"平均词向量"，观察性能变化。
回答一个问题：**顺序信息（LSTM 提供的）在这份数据上到底贡献了多少？**

## 二、数据集

| 项目 | 说明 |
|---|---|
| 来源 | 自建（用户手写） |
| 规模 | 20 条中文短评（10 好评 + 10 差评） |
| 领域 | 餐饮（服务、味道、环境、价格） |
| 分词 | 字符级（`for ch in text`），无标点 |
| 字表 | 127 个字符（"学号"式编号，出现顺序决定编号） |
| OOV 处理 | `<unk>` + `word2id.get(ch, UNK_ID)`（测试句中"烂"触发过 KeyError，已用 `.get` 修复） |

**泛化测试句**（字全部在字表内，但整句从未参与训练）：
- "好吃不贵"（好评）→ 字：好(8) 吃(35) 不(81) 贵(94)
- "贵不好吃"（差评）→ 字：贵(94) 不(81) 好(8) 吃(35) —— 与上一句**同字异序**
- "味道不差"（好评）→ 字：味(9) 道(10) 不(81) 差(101)

## 三、模型（消融对照）

```
基线版（LSTM）：  Embedding(128→16) → LSTM(16→32) → fc(h[-1]) → 2类
消融版（平均）：  Embedding(128→16) → mean(dim=1) → fc → 2类
```

消融规矩：**一次只拆一个部件**——除模型中间层外，数据管道、训练循环、损失函数完全一致。

⚠️ 消融版代码注意：删掉 LSTM 后，fc 输入维度必须从 `hidden_dim(32)` 改为 `embed_dim(16)`（维度链条：每层输入 = 上一层输出）。

## 四、超参数

| 超参 | 值 |
|---|---|
| vocab_size | 128（127 字 + <unk>） |
| embed_dim | 16 |
| hidden_dim | 32（仅 LSTM 版） |
| 损失 | CrossEntropyLoss |
| 优化器 | Adam，lr=0.01 |
| 梯度裁剪 | clip_grad_norm_(1.0)（LSTM 必需，平均版冗余但无害） |
| epochs | 100（20 条数据 → 必然过拟合，预期内） |

## 五、实验结果

### 5.1 训练集 20 条

| 模型 | 训练准确率 |
|---|---|
| LSTM | 100%（过拟合） |
| 平均词向量 | 100%（过拟合） |

> 两版都过拟合到 100%——20 条数据训练 acc 全对**不是能力**，是背题。

### 5.2 泛化测试（未训练过的句子）

| 测试句 | 真实 | LSTM 版 | 平均版 |
|---|---|---|---|
| 好吃不贵（好评） | 0 | ❌ 1 | ✅ 0 |
| 贵不好吃（差评） | 1 | ❌ 0 | ❌ 0 |
| 味道不差（好评） | 0 | ❌ 1 | ✅ 0 |
| **命中率** | | **0 / 3** | **2 / 3** |

### 5.3 关键 logits 证据

```
平均版：
  好吃不贵 -> [ 2.6502, -2.9276] -> 0
  贵不好吃 -> [ 2.6502, -2.9276] -> 0   ← 与上句逐位相同（差 1e-7，浮点噪声）
LSTM 版：
  好吃不贵 -> [-1.3070,  1.2639] -> 1   ← 句尾"贵"决定
  贵不好吃 -> [ 2.2722, -2.3198] -> 0   ← 句尾"好吃"决定
  味道不差 -> [-2.1604,  2.0171] -> 1   ← 句尾"差"决定
```

## 六、分析与结论（消融实验产出）

1. **顺序被抹除的实锤**："好吃不贵"和"贵不好吃"在平均版眼里是**同一句话**（logits 逐位相同）。平均向量丢弃了排列信息，这是数学必然，不是 bug。

2. **LSTM 近因偏差（recency bias）**：`h[-1]` 是最后一个字的记忆，权重最高。三句测试句的错误全部由**句尾字**决定（贵→差评、好吃→好评、差→差评）。LSTM 没学会否定结构，只学会了"记住结局"。

3. **平均版高频词绑架**：两版都判"好吃不贵"为好评——不是因为理解了"不贵"，而是"好"在训练集中出现频率远超"贵"（服务态度好/味道好/好吃 vs 仅"太贵了"一次），embedding 更新次数多 → 向量信号强 → 平均时一票顶三票。与第 13 周 IMDB 错误分析中的"高频词绑架"同源。

4. **消融结论**：在 20 条小数据上，**LSTM 的顺序能力没有转化为泛化收益**——两版都过拟合，泛化测试都靠"抓关键词"瞎猜（LSTM 抓句尾、平均版抓高频）。顺序信息确实被拆掉了吗？拆了，但对这份数据没有帮助。**这是消融实验最有价值的负结果**：顺序能力需要更大的数据量和更长的训练才能真正体现。

5. **过拟合标准诊断**：训练 acc 100% + 未见过句子露馅 = 背题，不是学会。以后看到"训练高、测试低"先想到过拟合，不要怀疑代码写错。
